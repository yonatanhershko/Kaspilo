# שחרור לחנויות — מה לעשות ואיפה

גרסה 1.0.0. אנדרואיד: בדיקה סגורה (12 בודקים × 14 יום). אייפון: TestFlight פנימי בלבד, עד שנסיים את התשלום דרך אפל.

## 0. פריסה (כבר רץ)

GitHub → Actions → "Deploy to production" → הריצה האחרונה → **Review deployments → production → Approve**. יש שני אישורים: אחד להגירות ואחד לבנייה.

אחרי האישור:

- ההגירות רצות על הפרוד.
- הבניות יוצאות ל-expo.dev, בערך 20–30 דקות.
- בנייה של אייפון עולה לבד ל-TestFlight.
- בנייה של אנדרואיד מייצרת קובץ `.aab` שמורידים ידנית.

## 1. משתמש הדגמה לבודקים (אפל + גוגל)

1. באפליקציית הפרוד: הרשמה עם אימייל `mykaspilo+review@gmail.com`. הסימן `+` מגיע לאותה תיבת דואר.
2. הסיסמה:
   - יוצרים אותה במנהל הסיסמאות שלך.
   - לפחות 12 תווים.
   - לא סיסמה שאתה משתמש בה במקום אחר. השרת דוחה סיסמה שדלפה.
3. בלוח הניהול: לאשר את המשתמש, תוכנית `family` (בלי תוקף).
4. להיכנס איתו ולהוסיף כמה הכנסות, הוצאות ויעד אחד, כדי שהבודק לא יראה מסכים ריקים.
5. את האימייל והסיסמה נותנים לבודקים רק בטפסים של החנויות (ראו למטה). לא ב-git.

## 2. אנדרואיד — Google Play Console

Play Console → **Create app**:

- שם: Kaspilo.
- שפת ברירת מחדל: עברית (he-IL).
- App (לא Game).
- Free.
- לסמן את ההצהרות.

### 2ג. Data safety (הצהרת נתונים)

- **נאסף:**
  - שם ואימייל (חשבון).
  - נתונים פיננסיים: הכנסות, הוצאות ויעדים שהמשתמש מזין.
  - מזהה מכשיר להתראות (push token).
  - נתוני שימוש בסיסיים (analytics פנימי).
- **לא נמכר**, ולא משותף עם צד שלישי.
- **מוצפן בהעברה:** Yes.
- **אפשר לבקש מחיקה:** Yes.
- **זיהוי רכישה (התראות ארנק):**
  - הסכום ושם בית העסק נקראים על המכשיר.
  - נשלחים לשרת רק כשהמשתמש שומר את ההוצאה, ואז הם כבר "נתונים פיננסיים שהמשתמש הזין".

### 2ד. דף בחנות (Grow → Store presence → Main store listing)

- שם, עד 30 תווים: `Kaspilo`.
- תיאור קצר, עד 80 תווים.
- תיאור מלא, עד 4000 תווים.
- אייקון: 512×512 PNG.
- Feature graphic: 1024×500, חובה.
- צילומי מסך: 2–8.
- להוסיף תרגום לאנגלית (en-US) עם אותם שדות.

### 2ה. העלאת הבנייה
1. expo.dev → kaspilo → Builds → בניית אנדרואיד production → **Download** (`.aab`).
2. Play Console → Testing → **Closed testing** → Create track (או Alpha) → Create release → להעלות את ה-`.aab`.
   - הפעם הראשונה חייבת להיות ידנית.
   - לאשר Play App Signing.
3. Release notes: "גרסה ראשונה לבודקים".
4. Testers:
   - רשימת אימיילים, או קבוצת גוגל עם 12 הבודקים.
   - להעתיק את **קישור ההצטרפות** ולשלוח להם.
5. Send for review. בדיקה של מסלול סגור לוקחת בדרך כלל כמה שעות עד יומיים.

### 2ו. חשוב אחרי ההעלאה הראשונה
- **התחברות עם גוגל באנדרואיד לא תעבוד בלי השלב הזה:**
  1. Play Console → Setup → App integrity → להעתיק את שני ה-SHA-1 (App signing key ו-Upload key).
  2. Google Cloud (פרויקט finny-f9dba) → Credentials → ליצור **OAuth client מסוג Android** לכל SHA-1, עם החבילה `com.kaspilo.app`.
- **בודקים:**
  - כל בודק שנרשם, לאשר בלוח הניהול (חינם), אחרת הוא תקוע במסך ההמתנה.
  - גוגל ישאלו בסוף על המעורבות שלהם.
  - הם צריכים להישאר רשומים 14 יום ברציפות.
- **התראות push באנדרואיד:**
  - בלי Firebase הן לא עובדות. האפליקציה לא קורסת, פשוט אין push.
  - אפשר לדחות. כשרוצים: `docs/notifications-setup.md` → להוסיף את `com.kaspilo.app` ב-Firebase ולהעלות את `GOOGLE_SERVICES_JSON` לסביבת production ב-EAS.
  - אחרי זה צריך בנייה חדשה.
- **אחרי 14 יום:** Dashboard → **Apply for production** → לענות על השאלון.

## 3. אייפון — TestFlight (בדיקה שלך)

1. App Store Connect → Kaspilo → **TestFlight**:
   - הבנייה מופיעה אחרי עיבוד של 10–30 דקות.
   - הצהרת ההצפנה כבר מוגדרת באפליקציה.
2. Internal Testing → קבוצה → להוסיף את עצמך (ועד 100 אנשים מהצוות שלך ב-App Store Connect). **בלי בדיקה של אפל.**
3. באייפון: אפליקציית TestFlight → Install.
4. מה לבדוק:
   - הרשמה עם אימייל, גוגל ואפל.
   - אישור מלוח הניהול → האפליקציה נפתחת.
   - הוספת הוצאה.
   - יעד + "כבר חסכתי".
   - שכחתי סיסמה.
   - מחיקת חשבון (במשתמש זמני).

בודקים חיצוניים ב-TestFlight צריכים בדיקה קצרה של אפל. כרגע אין בזה צורך.
